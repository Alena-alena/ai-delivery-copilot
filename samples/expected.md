# Эталон для проверки AI-анализа (expected.md)

Набор синтетический: вымышленная сеть клиник Smile Dental Network и проект ClinicBook (онлайн-запись к стоматологу). Реальных данных нет.
Файлы в папке `samples/` и этот документ используются для ручной оценки качества в `docs/eval-log.md`.

## Файлы

| Файл | Что это | Зачем |
|---|---|---|
| `01_clinicbook_requirements_en.pdf` | ТЗ, 2 стр., EN, есть текстовый слой | основной источник требований |
| `02_meeting_notes_en.docx` | Заметки встречи, EN, две таблицы | проверка DOCX и таблиц; решения, которые противоречат ТЗ |
| `03_client_email_ru_cp1251.txt` | Письмо клиента, RU, кодировка cp1251 | проверка кодировки и русских цитат |
| `04_vendor_notes_with_injection.txt` | Заметки SMS-провайдера, EN, UTF-8 | prompt injection |
| `05_scanned_addendum_no_text.pdf` | Скан без текстового слоя | ошибка PDF_NO_TEXT_LAYER |
| `06_corrupted.pdf` | Битый PDF с корректным заголовком | ошибка FILE_CORRUPTED |
| `07_fake_extension.pdf` | Не PDF (сигнатура MZ) под видом PDF | отклонение по magic bytes |

Файл для проверки лимита создаётся командой: `head -c 11000000 /dev/zero > /tmp/too_big.pdf`. Ожидается FILE_TOO_LARGE при лимите 10 МБ.

## Пробелы, которые AI должен найти (минимум 5 из 7)

| ID | Пробел | Где | Почему это пробел |
|---|---|---|---|
| G-1 | Нет правил отмены | 01, F-4 | Нет срока отмены, нет судьбы депозита |
| G-2 | Неясно «напоминание перед приёмом» | 01, F-5 | Не указано за сколько, по какому каналу. Ответ лежит в скане 05, который система прочитать не может, поэтому пробел остаётся открытым |
| G-3 | «Несколько языков» | 01, F-10 | Не указано, какие именно |
| G-4 | Права ролей не определены | 01, раздел «Roles» (стр. 2) | Не сказано, что видит регистратор и врач, особенно в медицинских данных. Отдельного требования нет, пробел «отсутствует в документах» |
| G-5 | «Высокая доступность» | 01, NF-3 | Нет измеримой цели (процент доступности) |

| G-7 | Интеграция с CRM | 03, п. 3 | Не указано, какая CRM, какие данные и в каком направлении |

## Противоречия, которые AI должен найти (минимум 3 из 5)

| ID | Сторона A | Сторона B | Суть |
|---|---|---|---|
| C-1 | 01, F-2 (стр. 1): «All appointment slots are 30 minutes long» | 02, решение 1: «appointment slots will be 15 minutes long» | Длительность слота |
| C-2 | 01, F-1 и NF-5: регистрация по email и паролю | 03, п. 1: «только по номеру телефона ... Пароли мы использовать не хотим» | Способ входа |
| C-3 | 01, F-8: обязательный онлайн-депозит | 02, решение 2: «online payments are out of scope for version 1» | Онлайн-оплата |
| C-4 | 01, NF-4: данные только в ЕС | 03, п. 2: хостинг US East, «Хранение данных пациентов тоже будет там» | Расположение данных |
| C-5 | 01, F-6: регистратор может отменять записи за пациента | 01, BR-1 (стр. 2): отменить может только пациент, создавший запись | Кто может отменять. Противоречие внутри одного документа |

Для каждого противоречия обе цитаты должны быть проверены по тексту источника. Формулировка в интерфейсе: «возможное противоречие».

## Как оценивать

Для каждого прогона заполни в `docs/eval-log.md`:

- найдено требований из 29, пропущено, выдуманных (нет в документах);
- найдено пробелов из 7 и ложных пробелов;
- найдено противоречий из 5 и ложных противоречий;
- у скольких находок цитата подтвердилась по тексту.

Первый прогон служит базовой линией. После каждой смены промпта сравнивай с ним.
